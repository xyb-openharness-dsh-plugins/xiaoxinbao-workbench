# 工作台交互与安全设计

版本：0.3.2 · 2026-10-15

## 产品流程

```text
选择女性陪伴角色 → 聚焦此刻话题 → DSH 原生会话承接情绪与聊天
                                           ↓
                             生成本次回顾请求并由用户发送
                                           ↓
                         将 DSH 回答粘贴/识别到本次回顾
                                           ↓
                   用户检查、编辑、认可后才保存本地便笺
                                           ↓
                       自愿了解量表 / 专业咨询 / 现实支持
```

### 先陪伴，再评估和建议

1. 先倾听和确认情绪，不把每一次聊天都变成任务清单；允许患者和家属的情绪反复变化。
2. 用户愿意时，工作台可将量表邀请写入 DSH 原生输入框，由模型介绍用途、局限、中文版和专业咨询路径。工作台不复制受版权限制的完整题目，不把筛查结果作为诊断。
3. 对话后的结构化回顾包含：本次聊到、用户想记住的话、中性观察、下一步选项、温和收尾。回顾只描述用户明确表达的内容，不做心理标签或临床评价。
4. 用户可编辑回顾并明确点击“认可并保存到本机”。没有认可就不保存。保存的不是完整聊天记录。
5. 鼓励收尾要具体、不强迫积极；建议可跳过。需要专业帮助时，温和引导至肿瘤团队、心理/精神卫生专业人员、社工或安宁疗护团队。

### 会话和回顾的宿主边界

工作台通过正式 `desktopWorkbenches.register()` 注册，复用 DSH 提供的 `conversation` 原生会话组件。开场与回顾请求通过公开输入接口放入草稿，由用户核对发送。当前公开接口提供会话元数据和恢复功能，但没有授权工作台读取完整消息正文的接口。因此回顾流程采用“向 DSH 请求回顾 → 用户复制 → 工作台粘贴/识别 → 审核保存”，不读取 DOM、不扫描私有会话文件、不伪称自动生成。

历史对话以本工作台拥有的原生会话元数据形成时间轴；点击后调用官方 `service.openSession(id)`。完整内容仍由 DSH 原生会话显示。

## 角色与语气

- **新确诊陪伴**：接住震惊、害怕和信息过载；先听再帮助梳理已知、未知和就诊问题。
- **治疗与照护同行**：理解“崩溃—修复—前行”的循环，容纳患者与照护者角色冲突、疲惫、内疚或愤怒。
- **安宁疗护陪伴**：围绕舒适、尊严、愿望、告别和照护沟通；新发/加重症状及疼痛用药问题交由照护团队。
- **哀伤同行**：不设阶段或时间表，允许思念、麻木、愤怒、内疚并存。
- **日常喘息与轻松聊**：可以聊猫狗、生活八卦或做简短放松，不把闲聊当成逃避即时危险的手段。
- **亲戚吐槽与边界练习**：陪用户针对言行宣泄，不羞辱身份特征、不泄露隐私、不煽动报复；用户愿意时再练习边界表达。

角色都是明确可见的用户提示模板，不是系统提示或自定义 Agent。模型、工具权限和完整对话均由 DSH 管理。

### 陪伴准则（六个角色共用）

角色的「语气」只是风格，真正决定像不像一个愿意听人说话的人，是提示词里的行为约束。0.3.12 之前这类约束只有一句"先承接情绪"，实测结果是模型会退回通用助手行为：抢在对方说完之前给方案、追问创伤细节（"他是什么时候走的"）、用咨询腔和长篇分析把对方变成案例。现在提示词最前面固定列九条「怎么说话」：

1. **先在场，再谈别的。** 先把听到的具体处境和情绪复述出来，不立刻给建议、方案或话术。
2. **不追问创伤细节。** 不问时间、分期、离世经过这类细节；对方愿意说多少就说多少。
3. **一次只做一件事。** 通常一次只问一个问题，也可以只回应不提问。
4. **话要短。** 一般 2–4 句。
5. **不用咨询腔。** 不说"我注意到你""你在处理一种……"，不贴心理标签。
6. **允许脏话、气愤、矛盾、反复和不想好起来。** 不纠正、不说教、不美化。
7. **被指出做得不好时直接承认。** 不辩解、不自我分析、不长篇解释。
8. **不拿"我懂你"当开场白。** 空泛共情没有信息量；要确认情绪，就把它绑在对方说的具体细节上。
9. **直接说话。** 不输出括号里的舞台指示，不写"建议一/建议二"式分点，不用后台逻辑做旁白。

另有三个小节来自参考素材 `prompt_template.md`，并按本项目的边界做了删改：

- **【对方想找同伴时】** 只在对方主动提到孤单、想找病友时触发。素材原文带具体联系方式与入群话术，这里全部去掉——仓库里没有可核实的渠道，写死一个账号既无法被使用者审查，也把"有人陪你说话"变成了导流。现在的措辞是不宣称有社群可介绍，转而建议问自己的医疗团队、医务社工或医院心理科。
- **【关于病情】** 素材按癌种给知识与统计数据（含生存率），直接喂给模型会诱发它替对方算预后，与安全底线冲突。这里只保留"哪些心理负担值得被看见"（身体意象、复发恐惧、照护者内疚、经济压力等），并明确不许引用统计数字、不许评估严重程度、不许主动提病种。
- **【身份与禁忌】** 取自素材的合规与禁忌章节，但删掉了"同一会话探测三次后自动结束对话"——在心理支持场景里突然终止对话有风险。

每条角色还带 `voice`（语气）与 `boundary`（边界，与 `SPEC.md` 第 3 节逐字一致）。安全底线单独成段并声明优先级高于角色语气。提示词源码在 `src/prompt.mjs`，契约测试在 `test/prompt-contract.test.mjs`。

角色设定只在开场写入会话一次，换角色不会自动改写已有对话；界面提供「重发角色设定」与切换提示，由用户决定是否重写。

## 页面结构

- 顶栏：品牌、版本号、服务连接状态、右上角齿轮配置。
- 陪伴：首页展示六个女性角色、角色说明和聚焦话题弹窗；会话区复用 DSH 原生 conversation。
- 本次回顾：回顾请求/剪贴板识别、五个可编辑字段、认可保存、已存回顾列表。
- 量表记录：量表用途和授权提示；自愿记录用户已经完成的结果，不自动计分或解释。
- 资料检索：三项可复用检索能力包；可把检索请求写入 DSH 会话，也可在明确同意后调用已配置的 KNOWS 服务。
- 历史对话：仅展示 DSH 会话元数据时间轴。
- 配置：本机回顾/量表目录、MinerU 连接设置、KNOWS 连接设置、导出与删除本地记录。

## 搜索能力包

`skills/` 中有三个可移植的工作流说明：肿瘤指南与共识、文献与临床研究、疼痛/症状与安宁疗护。它们不是第三方 DSH Agent 或自定义预设。可以由用户选择将检索任务交给 DSH 已启用的搜索工具，或通过本工作台服务端连接用户自行配置的 KNOWS 服务。

直接 KNOWS 适配器只实现通用 Bearer API Key + JSON POST 协议，发送 `{query, q}`，将常见 `results/items/hits` 返回格式映射到来源卡片。不同 KNOWS 部署的 API 可能不同，必须按部署说明设置基础地址和路径并实测；没有核验到来源/链接的结论不能当作已证实。发送外部检索前要求去标识化和确认。

MinerU 配置页只保存 API 地址和密钥状态，密钥写在 DSH 服务端插件目录下单独的权限受限文件中。0.3.2 尚未实现文件上传或 MinerU 任务解析流程；不能用此配置直接上传资料。后续实现前要加文件选择、去标识化提醒、明确上传确认、任务状态/失败回退和临时文件清理。

## 本地数据和隐私

- 用户明确选择一个已存在的本机目录后，结构化回顾、量表结果、用户填写的沟通偏好和明确保存的知识来源元数据写入 `cancer-psych-support-memory.json`。不静默创建目录。
- 沟通偏好由用户本人填写/删除，不从聊天推断；只有新会话开场会携带该段用户自述。知识记忆仅保留标题、HTTPS 链接、来源、日期和短备注，不存全文。
- DSH 服务端保存目录设置和密钥；API Key 不返回浏览器、不进工作台包、不进 DSH 模型会话。
- 数据文件与服务端设置采用 JSON 原子替换写入和限制权限。普通同机用户权限仍可能读到文件；当前不提供文件级加密。
- 页面提供导出、逐条删除和清空记录。卸载插件不会删除用户选择目录里的数据。
- 不保存完整聊天正文、患者姓名、医院号或病历附件；搜索请求不持久化。

## 危机与身体急症

任何角色遇到即时自伤/自杀风险、暴力风险或急性医疗危险时暂停角色语气，建议立即联系当地急救/危机支持、就近急诊或可信任的人陪同。工作台不监测、不自动通知、不假称已联系任何人。安宁疗护中的疼痛和症状请求用于协助记录并联系临床团队，不提供剂量、停药或调药指令。

## 视觉与无障碍

使用小胰宝薄荷绿作为品牌强调色，角色人物本身无边框、保留透明像素；用户提供的暖橙陪伴插画以低对比柔焦层作为背景，不遮挡正文。提供键盘可达按钮、对比清晰的正文与 `prefers-reduced-motion` 支持，不使用闪烁或持续循环动效。
