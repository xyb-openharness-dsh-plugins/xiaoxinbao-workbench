# UI 设计决策记录

## 参考原项目

花学工作台公开介绍的核心流程是选择工作区和旅伴后进入原生 DSH 聊天，可在会话旁切换旅伴，并由工作台入口处理历史会话；源码说明也将宿主客户端和业务客户端拆分。当前工作台借鉴“情境选择 → 角色化开场 → DSH 原生会话”的分工，不复制花学角色、游戏化玩法或表达内容。

来源：花学工作台 [项目介绍与使用说明](https://dpharness.com/plugin/gjz18342624299-arch/dsh-huaxue-workbench)。参考的是交互结构；其 DSH 兼容结论不适用于本项目。

## 本项目取舍

- 首屏不做医疗档案 Dashboard，按参考图采用 DSH 顶栏、中央提问、强调色主入口和底部人物角色展示，先帮助用户选择此刻需要的支持方式。
- 六位陪伴形象暂用 `assets/characters/*.svg` 原创占位图；可独立替换，不将角色绑定到具体患者或临床人员。
- 使用用户提供的陪伴插画作为透明柔焦背景层；叠加浅薄荷绿渐层，让插画保留生动色彩但不干扰正文。小胰宝透明 PNG 标识用于顶栏，薄荷绿作为主色。
- 六个角色以等宽、无重卡片边框的人物列展示；选择状态通过浅薄荷底色和薄荷绿短线标明。
- 不做自动轮播、闪烁状态点、循环打字机或惊喜动效；界面不应催促患者和家属。
- 不引入图标、动画或状态管理依赖；顶栏使用用户提供的小胰宝 PNG 标识。
- 角色卡片点击后打开聚焦话题浮窗；确认后调用 DSH 原生会话 API，并将角色背景与话题填入原生输入框；不自动发送。历史对话独立成页，按时间轴列出当前工作台拥有的原生会话并恢复到 DSH 窗口。独立 HTML 的主入口只显示预览说明，不伪造 DSH 连接。
