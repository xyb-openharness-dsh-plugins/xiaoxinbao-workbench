## 2026-10-15 · 0.3.5

### 单元 9：定位桌面端客户端加载异常

- DSH Desktop 显示错误 `Workbench registration requires a client package entry name.`，定位到 `sourcePackage()` 只接受宿主登记的客户端包 entry identity。
- 临时通过 pnpm 直接添加 `.tgz` 到应用 profile 能让文件加载，但没有生成 DSH 正式安装记录；该路径不满足桌面端来源校验，因此撤销临时添加，不把 provider 出现误报成接入完成。
- 恢复通用错误提示，正式包继续使用 `window.__ModuleLoader__` 和 `desktopWorkbenches.register()`；本机需通过 DSH Desktop 支持的正式安装入口或市场分发记录后，才能完成宿主端验收。
- 源码构建与 7 项检查通过；桌面端交互验收受限于当前市场不可用且应用未提供本地 `.tgz` 安装入口。

## 2026-10-15 · 0.3.2

### 单元 0：产品与宿主接口核对

- 按本项目 `AGENTS.md` 阅读 SPEC/UI 设计和本机 DSH `desktopWorkbenches` 客户端实现。
- 确认 workbench 可通过官方 `register()`、`newWorkspaceSession()`、`currentSession()`、`ownsSession()`、`openSession()` 管理宿主原生会话；原生输入草稿通过会话 scope 暴露的 `setDraft()` 写入。
- 确认公开接口没有向工作台提供会话消息正文读取 API。因此采用“请求 DSH 生成回顾 → 用户复制/粘贴 → 编辑认可”的桥接，不抓 DOM 或访问私有会话文件。
- 本机 DSH profile 中 web 搜索工具并未启用。工作台同时提供提示模板和可配置 KNOWS 连接，不宣称任意环境都能联网。
- 当时目标仓库尚未确认；该状态已在 0.3.3 由用户提供的正式仓库地址更新。

### 单元 1：服务端设置和密钥

- 新建 `dsh/settings-store.js`：校验数据目录、HTTPS/本机地址、KNOWS 路径；服务地址与 Key 分文件原子写入；客户端只得到密钥配置状态。
- MinerU 与 KNOWS Key 不放入浏览器、客户端 bundle、模型上下文或发行文件。
- 加入服务 API 请求大小限制、本机 DSH 授权会话检查、KNOWS 响应长度/URL 协议过滤。
- KNOWS 请求路径组合调整为保留配置基础路径（如 `/api/v1` + `/search`）。

### 单元 2：本地记忆与用户同意

- 新建 `dsh/record-store.js`：选定目录中只保存认可的回顾和用户自报量表结果；不保存完整会话。
- 回顾接口强制 `approved === true`；记录上限 2,000；字段长度设限；不静默创建目录；原子替换。
- 提供逐条删除、清空和 JSON 导出接口。
- 选择用户可见的 JSON 文件而非 SQLite/IndexedDB：数据小、易导出检查，且避免复制 DSH 会话正文。

### 单元 3：六角色 UI 与原生会话

- 重写 `src/client.js`、`src/client.css`：六位女性角色、话题浮窗、DSH 原生会话区、历史时间轴、配置/回顾/量表/检索标签页。
- 蓝发吐槽角色使用透明底年轻丸子头图；品牌 logo 和低对比柔焦背景图嵌入离线 bundle。
- 开场、搜索、量表说明和回顾请求都只写入原生输入框，不自动发送。
- 回顾按概要、用户原话、中性观察、下一步选项、鼓励收尾与量表邀请生成；用户编辑且点击认可后才保存。
- 修复客户端 `createElement` 括号错误两处；单独抽出 `renderReview()` 使页面层级可读，并修正历史列表闭合。

### 单元 4：检索和配置入口

- 增加三个随项目分发的可读 SKILL 流程：指南/共识、研究/试验、疼痛/安宁疗护。
- 配置页包括用户目录、MinerU 地址/Key、KNOWS 地址/路径/Key、密钥移除、JSON 导出/清除记录。
- MinerU 配置仅保存连接信息；当前不启用文件上传或解析，页面和文档已明确此限制。
- KNOWS API 协议为可配置的通用 Bearer Key + JSON POST；不同服务的协议兼容性须按真实服务联调。
